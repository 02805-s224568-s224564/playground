The group website and analysis code for **02805 Social Graphs and Interactions**
at DTU. Every week we publish one post analysing the shared Marvel/Wikipedia
network. The website and the notebooks that produce its figures live in this one
repository.

## Quick start

If you just cloned this repo, run this once:

```bash
./scripts/dev-setup.sh
```

That creates the Python environment **and** installs the git filter that keeps
notebook outputs out of commits. Do not skip it — see
[Why the setup script matters](#why-the-setup-script-matters).

Then:

| I want to… | Do this |
|---|---|
| Work on a notebook | `source .venv/bin/activate` then `jupyter lab` |
| Write a post | [Adding a post](#adding-a-post) — no Ruby needed |
| Preview the site locally | [Running the site locally](#running-the-site-locally) |
| Publish | Push to `main`. GitHub Actions builds and deploys it. |

## Repo layout

| Path | What's in it |
|---|---|
| `_posts/` | The weekly posts, one Markdown file each. **This is where you write.** |
| `notebooks/` | Jupyter notebooks — one per week's analysis |
| `data/` | The dataset. Gitignored; regenerated by notebooks/scripts. See `data/README.md` |
| `assets/figures/` | Plots exported from notebooks, referenced by posts |
| `scripts/` | Setup and data-fetching scripts |
| `_layouts/`, `_includes/`, `assets/css/` | The website's HTML and CSS. Rarely needs touching |

| `.claude/skills/` | Reserved for Claude Code skills; empty for now |

`notebooks/`, `data/` and `scripts/` are excluded from the published site — they
stay in the repo but are never uploaded to the web.

## Setting up the Python environment

Requires **Python 3.12 or newer** (`python3 --version` to check; download from
[python.org](https://www.python.org/downloads/) if needed).

**macOS / Linux**

```bash
./scripts/dev-setup.sh
source .venv/bin/activate
```

**Windows (PowerShell)** — the script is bash, so do the same steps by hand:

```powershell
py -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
nbstripout --install --attributes .gitattributes
```

Either way you end up with networkx, scipy, pandas, matplotlib, requests and
JupyterLab installed in a `.venv` folder that is gitignored. Start working with:

```bash
jupyter lab
```

To add a package, put it in `requirements.txt` **and** tell the other person, so
you don't end up on different versions.

### Why the setup script matters

The last step installs [nbstripout](https://github.com/kynan/nbstripout) as a git
filter. It strips outputs from notebooks as they are committed — your local
notebook keeps its plots and results, but what git stores has no outputs at all.

This matters because two people running the same notebook produce byte-different
outputs on every cell. Without stripping, *every* notebook change conflicts, and
the conflicts are unreadable base64 image blobs.

The catch: `.gitattributes` is committed, but the filter itself lives in
`.git/config`, which is **not** part of a clone. So each person must run the
setup once on each machine. If you skip it, git does not warn you — it silently
commits your outputs, and the `Check notebooks are stripped` job on the pull
request fails.

## Running the site locally

Optional. You only need this to preview design or layout changes — posts can be
written and pushed without ever installing Ruby.

### macOS

Jekyll needs Ruby ≥ 2.7 and macOS only ships 2.6, so install a current one:

```bash
brew install ruby@3.4
```

Homebrew keeps this "keg-only", meaning it deliberately does not put it on your
`PATH`. Add this line to `~/.zshrc` and open a new terminal:

```bash
export PATH="/opt/homebrew/opt/ruby@3.4/bin:/opt/homebrew/lib/ruby/gems/3.4.0/bin:$PATH"
```

⚠️ Note the `:$PATH` at the end. Without it you replace your entire `PATH` and
every command in that terminal stops working.

Check it took effect — this must **not** say 2.6.x:

```bash
ruby -v    # => ruby 3.4.10
```

### Windows

Install Ruby+Devkit from [rubyinstaller.org](https://rubyinstaller.org/)
(3.1 or newer), then continue below in a new terminal.

### Then, on any platform

```bash
bundle install                 # once, and after any Gemfile change
bundle exec jekyll serve
```

Open **<http://localhost:4000/playground/>** — note the `/playground/` part, the
bare root will 404. The site rebuilds as you edit; refresh to see changes.

### Not installing Ruby?

Push to a branch and open a pull request. The build runs in Actions, and a failed
build tells you what broke. Slower, but it needs nothing on your machine.

## Adding a post

1. **Create the file** in `_posts/`, named `YYYY-MM-DD-short-slug.md`. The date
   in the filename sets the post's date and its URL, so it is not optional.

   ```
   _posts/2026-09-15-who-holds-the-marvel-universe-together.md
   ```

2. **Start it with front matter** — the block between `---` lines:

   ```markdown
   ---
   title: "Who holds the Marvel universe together?"
   week: 1
   authors: [Johan Holmsteen, Joes Hasselriis Nicolaisen]
   notebook: notebooks/week1-centrality.ipynb
   ---

   The first paragraph is used as the excerpt on the front page, so make it
   say something.

   ## Then write normally

   Markdown: **bold**, `code`, [links](https://networkx.org), tables, and
   LaTeX like $c_B(v)$ if you need it.
   ```

   `week`, `authors` and `notebook` are all optional. `notebook` renders as a
   link to that file on GitHub, which is worth including — it is what lets a
   reader check your work.

3. **Save figures from your notebook** into `assets/figures/`, prefixed with the
   week so they stay sorted:

   ```python
   fig.savefig("../assets/figures/week1-degree-distribution.png",
               dpi=150, bbox_inches="tight")
   ```

4. **Put figures in the post with the `figure.html` include** — not with
   Markdown image syntax:

   ```liquid
   {% include figure.html
      src="/assets/figures/week1-degree-distribution.png"
      alt="Log-log degree distribution of the Marvel character graph"
      caption="Degree distribution on log-log axes. The tail is much heavier than a random graph of the same density."
      wide=true %}
   ```

   Use the include because the site is served from `/playground/`, and a plain
   `![](/assets/figures/x.png)` points at the wrong URL — it works locally and
   then 404s once deployed. The include fixes the path, adds the caption, and
   lazy-loads the image. `wide=true` lets a figure spill past the text column,
   which is what you want for network diagrams.

   Always write a real `alt` — it is what a screen reader, and the examiner
   skimming on a phone, actually gets.

5. **Commit and push to `main`.** The site rebuilds and redeploys automatically;
   it is usually live in about a minute.

To check a post before publishing, either run the site locally or push it to a
branch and open a pull request.

## How deployment works

`.github/workflows/pages.yml` runs on every push to `main`:

- **Build site** — installs Ruby and the gems, runs `jekyll build`, uploads the
  result.
- **Deploy to Pages** — publishes it.
- **Check notebooks are stripped** — fails if a committed notebook still has
  outputs, i.e. someone skipped `scripts/dev-setup.sh`. It does not block the
  deploy.

We build the site ourselves rather than letting GitHub Pages run its own Jekyll
build. That is deliberate: the Pages built-in build only allows a small
whitelist of plugins, and this way we can add any gem we want to the `Gemfile`.

The Pages source is set to **GitHub Actions** in the repository settings. If
someone ever switches it back to "Deploy from a branch", deploys will stop
working.

## Troubleshooting

**`ruby: command not found`, or everything in the terminal breaks**
Your `PATH` line in `~/.zshrc` is missing the trailing `:$PATH`. It must end with
`:$PATH` — otherwise it wipes out every other directory on your path.

**`jekyll serve` works but the page is blank or 404**
Use <http://localhost:4000/playground/>, not `http://localhost:4000/`.

**A figure shows locally but is broken on the live site**
You used Markdown image syntax instead of the `figure.html` include. See step 4
above.

**My post doesn't appear**
Check the filename is exactly `YYYY-MM-DD-slug.md`, and that the date is not in
the future — Jekyll hides future-dated posts by default.

**The site looks stale after a change**
`rm -rf _site .jekyll-cache` and run `bundle exec jekyll serve` again.

**A notebook conflict full of image data**
Someone committed a notebook without the filter installed. Both of you run
`./scripts/dev-setup.sh`, then re-commit the notebook.
